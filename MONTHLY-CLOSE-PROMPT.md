# Задание для ИИ-агента: подвести месяц в Кассе

Ты - агент (Claude Code, Codex или похожий) с доступом к терминалу. Человек раз в месяц даёт тебе папку проекта Кассы
и просит «подвести месяц». Ты собираешь все деньги месяца из банков, бирж и кошельков, сводишь их с записями Кассы,
спрашиваешь человека один раз по непонятным строкам и закрываешь месяц. После закрытия цифры месяца берутся из
закрытия: отчёт «Месяц» в Кассе показывает пометку «Месяц закрыт».

Работай только в этой папке. Касса уже установлена и запущена (`docker compose ps`: `api` healthy). Если нет,
сначала выполни `INSTALL-PROMPT.md`.

## Правила

- Ключи, пароли, токены и содержимое `.env` не печатай в чат и в журнал, не коммить, не вставляй в команды, которые
  выводят значение. Значения из `.env` читай внутри команды: `set -a; . ./.env; set +a`.
- Биржи читай только ключом с правом «только чтение». Никаких операций с деньгами: не торгуй, не выводи, не переводи.
- Платных сервисов и платных ключей не подключай.
- Банковские файлы человека лежат только в папке `import/`; она не попадает в git. Из этой папки файлы никуда не
  отправляй.
- Не придумывай суммы и даты. Чего нет в источнике, того нет. Строку, которую не поняла, не угадывай: она идёт в общий
  вопрос человеку.
- Один вопрос человеку на весь прогон (шаг 5). Не задавай вопросы по одному.
- Что не получилось прочитать, называй прямо: «не смогла прочитать файл X», «биржа Y пропущена: нет ключа».
  Пропуск источника не останавливает работу, но попадает в итог.

## Что подготовить заранее

Скажи человеку это в самом начале, одним сообщением, и жди его ответа. Минимум нужен только первый пункт.

1. **Выписки банков и карт за месяц.** Положить файлы в папку `import/` в корне проекта. Подходят CSV, XLSX, PDF, ZIP
   с этими файлами. Одна выписка на каждую карту или счёт. Название файла можно любое.
2. **Список способов оплаты.** Он уже есть в Кассе, ты его прочитаешь сам (шаг 1). Если способа нет в списке,
   скажи человеку, и он решит, добавлять ли его.
3. **Остатки наличных на конец месяца** (если человек записывает наличные в Кассе): одно число по каждой валюте. Их
   ты спросишь в общем вопросе на шаге 5, заранее готовить не нужно.
4. **Биржи, необязательно.** Нужен ключ только на чтение. Как его создать, написано ниже, в разделе «Биржа Bybit».
   Нет ключа - биржа пропускается, выписку с биржи можно положить в `import/` файлом.
5. **Кошельки, необязательно.** Публичные адреса можно записать открыто, в них нет ничего секретного: любой может
   посмотреть движения по адресу, но не может им распорядиться. Файл `import/wallets.txt`, одна строка на адрес:
   `сеть адрес название`, например `TRC20 T... мой холодный кошелёк`. Сети: TRC20 и ERC20.
6. **Банки.** У банков нет безопасного способа подключиться «только на чтение», поэтому выписки загружаются руками
   раз в месяц, в конце месяца. Объясни это человеку один раз: «выписки из банков нужно скачать самому в приложении
   банка и положить в `import/`, это занимает пять минут».

## Шаг 0. Какой месяц

Спроси или возьми из просьбы человека месяц вида `ГГГГ-ММ`. Если месяц ещё не закончился, скажи человеку и остановись.
Дальше в командах `<месяц>` - это он. Создай папки: `mkdir -p import close`.

Команды Кассы выполняются внутри контейнера `api`:
`docker compose exec -T api python -m kassa_api.month_close ...`.

Проверь, что месяц ещё не закрыт: `show <месяц>`. Если в ответе `"closed": true`, спроси человека, нужно ли закрыть
заново (тогда при загрузке будет ключ `--replace`).

## Шаг 1. Способы человека

```bash
docker compose exec -T api python -m kassa_api.methods list
```

Запиши названия способов. Команды нет (старая версия Кассы): возьми список из базы
`docker compose exec -T api python -c "import sqlite3;print([r[0] for r in sqlite3.connect('/data/kassa.db').execute('select title from methods where active=1')])"`.
Каждой строке закрытия нужен способ из этого списка: так в отчёте видно, откуда пришли деньги. Названия нового
способа не выдумывай: если банк в выписке неизвестен, спроси человека в общем вопросе (шаг 5).

## Шаг 2. Собери источники

Сделай по каждому источнику таблицу: дата, тип (доход, расход, перевод), сумма, валюта, способ, текст из выписки.
Считай и сверяй: число строк в таблице должно равняться числу операций в источнике.

**Выписки банков и карт (`import/`).** Прочитай каждый файл любого формата, который смогла (CSV, XLSX, PDF, текст
из PDF). Для PDF используй доступные инструменты (`pdftotext`, Python-библиотеки), для XLSX - `openpyxl`. Файл не
читается, парольный архив или скан без текста: назови файл человеку и пропусти. Не бросай работу из-за одного файла.
Запиши, какому способу из шага 1 соответствует каждый файл (по названию банка или карты в файле); непонятно -
в общий вопрос.

**Биржи (необязательно).** Для Bybit есть готовый скрипт, он только читает:

```bash
set -a; . ./.env; set +a
python3 scripts/exchange_bybit_readonly.py <месяц> --out-dir import
```

Ответ «биржа Bybit пропущена: нет ключа» - нормально: так и напиши в итоге, идём дальше. Скрипт создаёт
`import/bybit-<месяц>.csv`: депозиты и выводы за месяц. Для других бирж (Binance, OKX и т. д.) готового скрипта нет:
если человек положил выписку файлом, читай её как любую выписку; если дал ключ только на чтение, можно написать
небольшой скрипт по тому же образцу (`scripts/exchange_bybit_readonly.py`), но только на чтение и только если ключ
задан. Ключи лежат в `.env` как `KASSA_EXCHANGE_<ИМЯ>_KEY` и `KASSA_EXCHANGE_<ИМЯ>_SECRET`. Нет ключа: «биржа <имя>
пропущена: нет ключа».

**Кошельки (необязательно).** Если есть `import/wallets.txt` или `data/wallets.json`: по каждому адресу возьми
поступления и отправления за месяц из публичных обозревателей без платных ключей. TRC20: TronGrid
(`https://api.trongrid.io/v1/accounts/<адрес>/transactions/trc20`, параметры `only_confirmed=true`,
`min_timestamp`, `max_timestamp` в миллисекундах, `limit=200`). ERC20: Blockscout
(`https://eth.blockscout.com/api/v2/addresses/<адрес>/token-transfers?type=ERC-20`). Сети нет или обозреватель не
отвечает: напиши «кошелёк <название> пропущен: нет доступа к сети» и иди дальше. Перевод со своей биржи на свой
кошелёк - это перевод между своими счетами (шаг 3), а не доход.

**Записи Кассы за месяц.** Это то, что человек внёс сам (текстом, голосом, формой):

```bash
docker compose exec -T api python -m kassa_api.month_close export <месяц> > close/hand-<месяц>.json
```

Важно: после закрытия записи, внесённые руками, остаются в базе, но в отчётах не участвуют. Поэтому всё, что в них есть
и чего нет в выписках (чаще всего наличные), ты обязана перенести в файл закрытия.

## Шаг 3. Своди и разбирай по типам

Правила:

1. **Дубли.** Одна сумма, одна дата (разница до трёх дней) и один способ в двух источниках - это одна операция. Самое
   частое: запись человека в Кассе и строка той же карты в выписке. Оставляй банковскую строку (сумма точнее), а
   категорию и текст бери из записи человека. Сомневаешься (сумма похожа, но не равна, или способы разные) - обе
   строки остаются, а пара идёт в общий вопрос.
2. **Доход, расход, перевод.** Доход - деньги пришли снаружи. Расход - ушли наружу. Перевод между своими счетами - не
   доход и не расход: перевод с карты на наличные, с карты на биржу, с биржи на кошелёк, обмен валюты. Признак: у двух
   источников есть пара из ухода и прихода на близкую сумму в близкие даты (разница на комиссию и курс допустима).
   Комиссию перевода записывай отдельным расходом. Займ и возврат займа - тоже не доход и не расход, это вопрос
   человеку.
3. **Категории.** Расходу ставь короткую категорию словами человека (кафе, продукты, транспорт, жильё и т. д.).
   Доходу - «доход». Не знаешь - не ставь, Касса определит по тексту.
4. **Курсы.** Каждой строке нужна сумма в долларах США. Для USD, USDT, USDC она равна сумме. Для остальных валют
   возьми курс на дату закрытия (последний день месяца) и запиши в файле закрытия в поле `rates` с пометкой, откуда
   он (`rates_source`). Без курса месяц не загрузится.

## Шаг 4. Итоги для сверки

Посчитай итоги отдельно от строк, по сырым источникам: сумму доходов, сумму расходов в долларах и расходы по
категориям. Эти числа пойдут в поле `totals` файла закрытия. Касса сверит их со строками и откажется загружать месяц,
если они не сошлись. Если итоги не сходятся, найди причину (потерянная или дублированная строка), а не подгоняй числа.

## Шаг 5. Один пакет вопросов человеку

Собери все непонятные строки и вопросы и задай их одним сообщением, таблицей:

| Что | Дата | Сумма | Как выглядит в выписке | Варианты ответа |
|---|---|---|---|---|

В это же сообщение добавь: неизвестные банки или карты без способа (какой способ поставить), остатки наличных на конец
месяца, подозрения на дубли, займы, и список пропущенных источников (какая биржа, какой файл, какой кошелёк). Не
считай итог и не загружай ничего, пока человек не ответил. Ответы запиши в `close/answers-<месяц>.md` дословно, одной
таблицей, потом примени их к строкам. Новых вопросов после ответа не задавай; если что-то осталось неясным, выбери
безопасный вариант (расход вместо дохода) и назови это в итоге.

## Шаг 6. Файл закрытия

Собери `close/<месяц>.json` (папка `close/` не попадает в git):

```json
{
  "month": "2026-10",
  "rows": [
    {"date": "2026-10-01", "type": "income", "amount": "3000.00", "currency": "USD",
     "method": "Название способа", "category": "доход", "note": "короткий текст"},
    {"date": "2026-10-03", "type": "expense", "amount": "150.00", "currency": "TRY",
     "method": "Наличные", "category": "кафе", "note": "кофе", "rate": 0.03},
    {"date": "2026-10-05", "type": "transfer", "amount": "300.00", "currency": "USD",
     "method": "Карта", "to_method": "Наличные"}
  ],
  "rates": {"TRY": 0.029},
  "rates_source": "откуда взяты курсы",
  "totals": {"income_usd": "3000.00", "expense_usd": "25.00",
             "by_category": {"кафе": "4.50", "транспорт": "20.50"}}
}
```

Поля строки: `date` (в этом месяце), `type` (`income`, `expense`, `transfer`), `amount` больше нуля, `currency` (код
из латинских букв), `method` (название способа), `category`, `note` (до 200 знаков), необязательные `usd` (сумма
в долларах, если известна точно) и `rate` (долларов за единицу валюты). Порядок поиска суммы в долларах: `usd`
строки, сама сумма для USD/USDT/USDC, `rate` строки, `rates` файла.

Переводы записывай строками `transfer`: они не доходы и не расходы, Касса их только считает отдельным числом и в
отчёты не включает. Записи из `close/hand-<месяц>.json` внеси строками (они уже в этом формате).

## Шаг 7. Загрузи и проверь

```bash
docker compose exec -T api python -m kassa_api.month_close load - < close/<месяц>.json
docker compose exec -T api python -m kassa_api.month_close verify <месяц>
docker compose exec -T api python -m kassa_api.month_close show <месяц>
```

`load` печатает число загруженных строк и список созданных новых способов. Он безвреден при повторе: тот же файл не
добавляет ничего. Файл изменился, а месяц уже закрыт: повтори с `--replace`. Ответ `error rows_do_not_match_file_totals`
или `...categories`: итоги не сошлись со строками, вернись к шагу 4 и найди причину, месяц при этом не записан.
`verify` должен ответить «совпало»; если «не совпало», не говори, что месяц закрыт, найди причину.

Покажи человеку, куда смотреть: открыть Кассу, вкладка «Месяц», стрелками выбрать месяц. Под суммами должна быть
строка «Месяц закрыт. Итоги совпадают с закрытием.» и кнопка «Курсы» с курсами закрытия. Если там написано, что итоги не
совпадают, это ошибка, и ты возвращаешься к шагу 7. Расскажи итоги словами: доход, расход, остаток за месяц, расходы
по трём крупным категориям. Суммы называй человеку, секретов в них нет, но в журнал и логи кроме итогов ничего не
выводи.

## Шаг 8. Резервная копия

```bash
python3 scripts/backup_db.py
```

Покажи путь к копии. Файлы из `import/` и `close/` оставь у человека: удалять их или нет, решает он. Напомни, что
это личные данные и в git они не идут.

## Шаг 9. Итог человеку

Напиши коротко:
1. Месяц закрыт: да или нет, и что показывает проверка.
2. Что было прочитано (файлы, биржи, кошельки) и что пропущено, с причиной.
3. Сколько строк загружено, сколько переводов между своими счетами, сколько записей Кассы перекрыто закрытием.
4. Что ты решила сама по безопасному варианту (если было).
5. Где лежит резервная копия.
6. Что сделать в следующем месяце: скачать выписки в `import/` и позвать тебя снова.

## Биржа Bybit: как создать ключ только на чтение

Ключ создаёт человек, ты ему подсказываешь, но не просишь прислать ключ в чат.

1. Войти на bybit.com, нажать на значок профиля, пункт «API».
2. «Создать новый ключ», тип «Сгенерированные системой ключи API» (System-generated API Keys).
3. Название любое, например «Касса чтение». Права ключа: «Только чтение» (Read-Only). Пункты про торговлю, вывод
   средств и переводы не включать. Названия на сайте иногда меняются: главное, чтобы у ключа не было права на
   вывод и на торговлю.
4. Желательно привязать ключ к IP-адресу машины, где работает Касса. Без привязки Bybit может ограничить срок жизни
   ключа до трёх месяцев, тогда его придётся создавать заново.
5. Подтвердить создание (код из почты или приложения). Bybit покажет ключ и секрет один раз.
6. Вписать их в файл `.env` самому, в текстовом редакторе, двумя строками:
   `KASSA_EXCHANGE_BYBIT_KEY=...` и `KASSA_EXCHANGE_BYBIT_SECRET=...`. В чат не присылать. Файл `.env` в git не идёт.
7. Проверка: `set -a; . ./.env; set +a; python3 scripts/exchange_bybit_readonly.py <месяц> --out-dir import`.
   Ответ «записано N операций» - всё работает.

**Другие биржи.** Принцип тот же: в личном кабинете в разделе API создать ключ с правом только на чтение, без вывода и
без торговли, привязать к IP, вписать в `.env` как `KASSA_EXCHANGE_<ИМЯ>_KEY` и `KASSA_EXCHANGE_<ИМЯ>_SECRET`. Если
биржа не даёт отдельного права «только чтение», ключ не создавать, а скачивать выписку руками в `import/`.
