# Задание для ИИ-агента: установить Кассу

Ты - агент (Claude Code, Codex или похожий) с доступом к терминалу машины, на которую нужно поставить Кассу:
личную кассу в Telegram (бот + мини-приложение, текст и голос). Репозиторий уже склонирован, ты в его корне.
Про другие проекты и папки человека ничего знать не нужно, работай только в этой папке.

Правила работы:
- Токен бота и содержимое `.env` не печатай в чат и в журнал, не коммить, не вставляй в команды, которые выводят
  значение. Читай значения из `.env` внутри команд (`set -a; . ./.env; set +a`).
- Сначала спроси человека всё нужное (шаг 1), потом делай без лишних вопросов. Платных сервисов не подключай.
- Каждый шаг проверяй командой и показывай итог человеку одной строкой.

## Шаг 1. Спроси у человека

1. Токен бота: «Откройте @BotFather, команда `/newbot`, пришлите токен вида `123456:ABC...`».
2. Его числовой Telegram id: «Напишите @userinfobot, пришлите число из строки Id». Несколько человек - через запятую.
3. HTTPS-адрес для мини-приложения. Спроси: «Есть домен, направленный на эту машину, или нужен бесплатный
   временный адрес-туннель?» Домен: получи его имя. Туннель: см. шаг 4.
4. Необязательно, предложи значения по умолчанию: часовой пояс (имя IANA, например `Europe/Berlin`), нужно ли вечернее
   напоминание и во сколько, нужны ли голосовые (по умолчанию да).

## Шаг 2. Проверь окружение

```bash
docker --version && docker compose version
```

Docker нет - поставь его штатным способом для этой ОС (https://docs.docker.com/engine/install/) или остановись и
скажи человеку, что нужны права администратора для установки. Пользователь должен запускать `docker` без sudo
(иначе используй `sudo docker`). Свободного места нужно около 3 ГБ (образ и модель голоса).

## Шаг 3. Настрой `.env`

```bash
cp .env.example .env && chmod 600 .env
mkdir -p data
```

Заполни переменные (значения - ответы человека; редактируй файл программой, не показывая токен в выводе):
`KASSA_BOT_TOKEN`, `KASSA_ALLOWED_IDS`, `KASSA_PUBLIC_URL` (https, без слэша на конце), `KASSA_INTERNAL_TOKEN`
(сгенерируй: `openssl rand -hex 20`), `KASSA_PATH_TOKEN` (рекомендуется: `openssl rand -hex 20`).
Необязательные: `KASSA_TZ`, `KASSA_REMINDER_ENABLED` (`1`) и `KASSA_REMINDER_TIME` (`ЧЧ:ММ`), `KASSA_VOICE_ENABLED`
(`0` выключает голос), `KASSA_WHISPER_MODEL` (`tiny`, `base`, `small`). Допиши
`KASSA_UID=$(id -u)` и `KASSA_GID=$(id -g)` в `.env`, чтобы контейнеры могли писать в `./data`.
Туннель (шаг 4Б) удобнее поднять до запуска контейнеров и сразу вписать настоящий адрес; пока его нет, впиши временный `https://example.invalid` и поправь до `docker compose up`.

Проверь, что обязательные переменные непустые, не печатая значения:
`for k in KASSA_BOT_TOKEN KASSA_ALLOWED_IDS KASSA_PUBLIC_URL KASSA_INTERNAL_TOKEN; do grep -q "^$k=." .env && echo "$k ok" || echo "$k ПУСТО"; done`

## Шаг 4. HTTPS-адрес

Порт 8080 контейнера опубликован только на `127.0.0.1`. Нужно вывести его наружу по HTTPS.

**А. Домен.** Поставь обратный прокси с автоматическим сертификатом (Caddy):

```
<домен> {
    reverse_proxy 127.0.0.1:8080
}
```

Проверь, что домен указывает на эту машину (`dig +short <домен>`), порты 80 и 443 открыты. Адрес = `https://<домен>`.

**Б. Туннель без домена.** Выбери то, что уже есть или легко ставится:
- `cloudflared tunnel --url http://127.0.0.1:8080` (cloudflared quick tunnel): запусти в фоне через `setsid nohup ... &`, PID возьми через `pgrep -f "cloudflared tunnel"` (не `$!`: это PID обёртки), из его журнала возьми адрес
  `https://....trycloudflare.com`. Адрес меняется при перезапуске туннеля: предупреди человека.
- `tailscale funnel --bg 8080`, если установлен Tailscale и включён Funnel: адрес - `https://<имя-машины>.<tailnet>.ts.net`.

Впиши итоговый адрес в `KASSA_PUBLIC_URL` (без слэша на конце).

## Шаг 5. Собери и запусти

```bash
docker compose config -q && docker compose up -d --build
docker compose ps
```

Жди, пока `api` станет `healthy`, а `bot` - `running` (первая сборка 3-8 минут). Если не так, смотри
`docker compose logs --tail 50 api bot` (в журнале токенов нет) и чини причину: пустая обязательная переменная,
`KASSA_PUBLIC_URL` не https, нет прав на `./data` (проверь `KASSA_UID`/`KASSA_GID`).

## Шаг 6. Проверь

1. Локально: `set -a; . ./.env; set +a; curl -fsS "http://127.0.0.1:8080/${KASSA_PATH_TOKEN:+$KASSA_PATH_TOKEN/}healthz"` - ответ `ok`.
2. Снаружи: тот же путь на `$KASSA_PUBLIC_URL` - ответ `ok`; ответ 404 на адрес без префикса при заданном `KASSA_PATH_TOKEN` - норма.
3. Бот жив: `curl -fsS "https://api.telegram.org/bot${KASSA_BOT_TOKEN}/getMe"` - `"ok":true` (не показывай вывод целиком, он
   безвреден, но команду с токеном в логи не выноси).
4. Попроси человека: открыть бота, нажать `/start` (придёт кнопка «Касса»), написать «кофе 150 лир». Придёт карточка;
   «Верно» (или «Записать») откроет форму, «Записать» в форме сохранит запись. Убедись, что запись есть:
   `docker compose exec -T api python -c "import sqlite3;print(sqlite3.connect('/data/kassa.db').execute('select count(*) from transactions').fetchone()[0])"`
   - число больше нуля.
5. Голос (если включён): человек отправляет боту голосовое «кофе сто пятьдесят лир». Первое сообщение скачивает модель,
   это занимает минуты (следи `docker compose logs -f bot`). Придёт карточка. Не пришла: см. журнал бота; нет места
   или памяти - предложи `KASSA_WHISPER_MODEL=base` или `tiny` и `docker compose up -d`.
6. Если включено напоминание, проверь строку в `.env`; сработает оно в заданное время, если за день нет записей.
7. Сделай первую резервную копию: `python3 scripts/backup_db.py`; копии лежат в `backups/` в корне проекта, покажи путь.

## Шаг 7. Итог человеку

Напиши: адрес мини-приложения (без токена пути в публичных местах), что проверено (пункты 1-7), что осталось на
человеке (например, постоянный туннель после перезагрузки), где резервные копии, как обновлять
(`git pull && docker compose up -d --build`).

## Откат и удаление

- Остановить: `docker compose down` (данные остаются в `./data`).
- Вернуть прежнее состояние после неудачного обновления: `docker compose down`, `git checkout <прежний коммит>`, при
  необходимости восстановить базу из `backups/` (положить как `data/kassa.db`, удалить `data/kassa.db-wal` и
  `data/kassa.db-shm`), `docker compose up -d --build`.
- Удалить совсем (только по просьбе человека): `docker compose down --rmi local`, затем удалить папку проекта; бот
  удаляется у @BotFather командой `/deletebot`. Остановить туннель или прокси, если ты их ставил.
